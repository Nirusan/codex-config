# Record evidence-based progress

1. Locate the existing tracker or task record for this work and follow its conventions. Read the relevant entries; do not open every planning document or create a new tracker automatically.
2. Compare the recorded state with the actual change and available verification. Update only the affected task, acceptance items, and material blockers.
3. Keep implementation, automated checks, manual acceptance, and delivery distinct when they have separate requirements. Code existing does not prove it passed tests, reached users, or passed a device check.
4. Record a remaining check or dependency as pending or blocked, with the evidence needed to close it. Do not mark an item complete to make the plan look tidy.
5. Keep the entry brief and useful for resumption; link to durable evidence when available instead of pasting logs or chat history.

Do not reorder the roadmap, invent work, or change unrelated task status unless requested. If the current tracker is already accurate, make no edit.
